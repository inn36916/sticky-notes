# Windows 桌面便签续做计划

**目标**　把当前的图文工作卡片做成可以日用的桌面便签。用户能快速记下来、在需要时找回来、到点收到提醒。

**架构**　沿用 Electron、原生 HTML/CSS/JS、现有 IPC 和 JSON 持久化。搜索、归档和提醒扩展现有便签模型，边缘卡组复用现有窗口与收纳规则。保持现有富文本、截图和 Mermaid 的存储语义。

**依据**　2026-11-21 项目审查和当前源码。竞品功能参考 [Pinny Notes](https://pinnynotes.org/) 与 [Noty for Windows](https://github.com/mole88/noty-windows)，沿用本项目的界面设计并自行实现。

## 做哪些功能

| 批次 | 交付 | 借鉴来源 | 为什么排在这里 |
|---|---|---|---|
| 0 | 全局划词改为主动启用、全文搜索、大图文输入提速 | 本项目故障与 Noty 的搜索入口 | 新增整理功能之前，先让用户能顺畅写和找 |
| 1 | 单次提醒、归档与恢复、便签内勾选任务 | Pinny 的提醒、Noty 的归档与清单 | 形成「记录 → 行动 → 收尾」闭环 |
| 2 | 多张便签的边缘卡组、Markdown／纯文本导入导出 | Noty 的贴边卡组与文件交换 | 解决便签多了占屏幕、内容难带走 |
| 3 | 可分发的 Windows 便携版、选中文字的本地工具 | Pinny 的便携交付与右键工具 | 先降低试用门槛，再验证文本操作是否值得继续增加 |

本轮新增功能的主线是提醒、归档、任务和边缘卡组。自动划词的全格式恢复、整库加密、实时 Markdown 编辑、可配置全局快捷键、系统级重复提醒和更多转换格式留到后续立项。独立复用现有阅读模式满足临时防误编辑的需要，单独的锁定权限无需和本轮一起交付。

## 批次 0 · 修日用链路

### 0.1 全局划词改为主动启用

涉及 lib/migrations.js、main/global-overlay.js、src/dashboard.js 及对应设置页。新装默认关闭。现有安装升级时一次性关闭旧全局划词值，并在设置页说明变更与开启入口。现有记录里的 true 无法可靠区分默认值与主动选择，升级时统一处理。迁移只执行一次，此后用户主动开启可跨重启保留。便签内划词继续工作。

- [x] 先加迁移用例，覆盖新装、旧配置 true／false、升级后手动开启再重启。
- [x] 桌面验收用合成截图，关闭时切到外部应用划词，粘贴仍拿到原截图。打开开关时显示「取词会使用系统剪贴板」并验证浮窗可用。

实施记录（2026-11-21）：0.1 已实现，数据版本升为 v3，复用现有升级前快照机制；便签中心与托盘均提供开关和剪贴板提示。396 项 Node 测试及静态检查通过；13 套 Electron 测试均通过（其中两套修正版本断言后重跑）。外部应用划词与合成截图剪贴板验收已补做并通过，关闭浮窗迟到回报问题在 1.1.2 修复。

### 0.2 便签中心全文搜索

涉及 src/note.js、lib/dom-snapshot.js、main/ipc.js、preload.js 和 src/dashboard.js。现有 160 字 preview 只用于列表展示。主进程查询基于规范后的可见正文，按便签 ID 缓存搜索文本，正文或标题改变时更新。旧便签按需从保存的 HTML 提取，复用现有快照对图表与图片的正文规则。查询只给便签中心返回匹配 ID 与短上下文。

- [x] 用真实旧版便签数据结构建立测试，覆盖第 161 字以后命中、中文连续匹配、英文大小写、编辑与删除后索引更新。
- [x] 使用 500 张短便签做热查询，本机 P95 目标 100 ms 内。确认结果中有命中上下文，整篇正文和图片 data URL 无需经列表 IPC 广播。

实施记录（2026-11-21）：0.2 已实现。主进程按 ID 与 HTML 缓存搜索正文；旧 HTML 在无 Node 权限、禁止网络的隐藏解析页中使用 DOMParser，复用快照纯文本规则。标题直接读取最新值，正文变更下次查询更新缓存，删除后查询清除缓存。列表仍只传元数据，搜索仅传 ID 和最多 122 字上下文。隔离 v2 fixture 验证正常搜索入口；500 张短便签含 IPC 热查询 P95 为 3.7 ms。398 项 Node 测试、静态检查及 13 套 Electron 回归全部通过。首次查询需建立索引，此数字不代表冷查询。

### 0.3 大图文输入提速

涉及 src/note.js、preload.js、main/ipc.js 和现有图片插入／预览入口。先试把内联截图的大块数据从每键传输中移出。插图时登记一次，正文存稳定引用，沿用项目现有附件目录和协议；打开既有 data URL 便签后，首次编辑前先在隔离 fixture 上验证兼容迁移。附件落盘成功后才提交引用，失败时保留可读原内容。保存确认、退出写入屏障和旧数据的读取由现有回归守住。

- [x] 用 scripts/perf-input.js 建基线，并补一条模拟「通过现有插图入口生成便签」的端到端用例。用等量、等尺寸图片和相同输入节拍对比前后版本。
- [x] 首轮目标是约 4 MB 图文等价场景每键处理 P95 低于 50 ms，2 KB 纯文本 P95 低于 10 ms。旧图库打开、预览、复制图片和立即退出恢复均通过。
- [x] 若附件引用方案达到目标，按现有同步保存协议收口。若未达到，记录序列化和 IPC 的耗时分项，再决定是否按编辑增量传输。

## 批次 1 · 提醒、归档和任务

### 1.1 单次提醒

新增 main/reminders.js，接入 main.js 启动与恢复、main/ipc.js、preload.js、便签菜单和便签中心。每张便签最多一个提醒，持久化到期时间与处理状态，支持设置、改期和取消。到期时显示系统通知，点击打开原便签。主进程每次只安排最近的一项，休眠恢复与应用重启后重新扫描。应用完全退出期间的到期提醒在下次启动时补发，界面直接说明这一行为。

- [x] 使用可控时钟先测试到期、改期、取消、删除、休眠跨过到期时间、到期后重启。以「提醒状态」区分待发和已处理，避免常规重启重复弹出。
- [ ] 真机验收把置顶便签隐藏后设一分钟提醒，通知点击能打开正确便签。断网时可运行。Windows 关闭通知时，便签中心仍能看到到期条目。

### 1.2 归档与恢复

在 lib/migrations.js 给便签增加可空的 archivedAt。由 main/windows.js 收口归档、恢复、窗口显示与保存，main/ipc.js 暴露动作，src/dashboard.js 添加归档筛选。归档从桌面和活跃列表移除，保留正文、附件和原窗口位置。归档时取消待发提醒。恢复后出现在活跃列表，由用户打开。

- [x] 测试旧便签按活跃处理，归档后跨重启保持隐藏，全文搜索可在归档页命中，恢复后图文和窗口位置完整。
- [x] 备份格式随新字段升级，使用带截图、Mermaid 和转换附件的样例走归档、重启、恢复一遍。

### 1.3 便签内勾选任务

涉及 src/note.html、src/note.js、lib/dom-snapshot.js。在现有富文本中保存可勾选的列表项和完成状态，继续走便签自己的撤销和保存入口。任务仅属于当前便签。阅读模式下可查看状态，进入编辑模式后勾选。

- [x] 测试新增、勾选、取消、撤销、粘贴、立即退出与重启。确认完成状态和顺序一致，截图与 Mermaid 块能共存，统计字数和搜索可正常使用。

- [ ] 测试两块不同缩放比例的显示器。三张便签收纳后，一个入口能分别打开正确卡片。设置键盘可达入口并测试 Esc 收起。
