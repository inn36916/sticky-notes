## 1. 评估结论

**总评**：在单用户 Windows 桌面便签场景下，已把「编辑 → 富文本/图片/图表插入 → 截图标注 → 画板 → 页面内/系统级划词 AI → 贴边收纳」串成完整闭环，功能密度高、边界处理细；但「数据可带走、可升级、可回归、可分发」这条工程化链路几乎空白，属典型**功能可用、工程化待补**。架构健康度评为 **C（可用但不可演进）**。

| 维度 | 分级 | 依据 |
|---|---|---|
| 功能可用性 | 高 | 14 组能力 / 6 类窗口 / 43 个 IPC；`contextIsolation:true` + `nodeIntegration:false` + CSP |
| 数据可靠性 | **中偏低** | 有原子写与损坏备份，但 L-1 几何污染、N-01 退出竞态、N-02 高版本静默降级、无写前快照、写盘失败静默 |
| 用户体验 | 中高 | 「隐藏≠丢失」、AI 错误码人话、rAF 兜底；但保存状态是错误确认、6 类窗口能力不对齐 |
| 可见性能可预测性 | 中（未实测） | 全量写盘、120ms 常驻轮询、每便签一窗口均为线性成本，缺真实 N |
| 可维护性 | 低 | 43 IPC 无契约、`main.js` 单文件职责混杂、无测试/lint/CI、文档漂移 |
| 可分发性 | 低 | 源码直跑、未打包未签名、无开机自启、外部 Python3 硬依赖 |
| 质量风险 | **高** | 零自动化回归 + 唯一正常退出路径从未验证 + 真实数据中已有现成待触发样本 |

**最该先做的一件事**：把「退出路径的持久化收口」做成唯一入口，并用最小回归网锁住。理由：L-1（`main.js:2316`）与 N-01（`note.js:1010/1012/1213`）**同源**——都是 `before-quit` 绕过既有 guard 直接收口；`README:783-784` 已记载同坑复发，说明无回归网时会再犯。

**推荐顺序（架构师定夺，不可拆分发版）**：

### 3.4 可见性能与异常处理

**性能（PF-01…PF-12，均标「需实测」）**：启动 `i*60ms` 排队（`:2299`）；250ms 防抖全量 `JSON.stringify` + 同步 IO（`:88-101`）；三级串联防抖 180→350→250ms（最坏常量叠加 780ms）+ Mermaid 450ms 旁路（`note.js:394/89/729`、`main.js:90`）；120ms 贴边轮询常驻（`:716`）；每便签一个 BrowserWindow + `alwaysOnTop('screen-saver')` + `backgroundThrottling:false`（`:800-847`）；`desktopCapturer` 固定 260ms 等待在 `main.js:1384`（**非 `1268-1279`，V-16 修正**）；SSE 每 delta 一次 IPC（`:383-453`）；Mermaid 每窗口重复加载 vendor（`:note.js:555-582`）；探针取词 `COPY_DELAY=0.12s` + 剪贴板轮询 20ms / 最长 0.5s（`sel-probe.py:61-62`）；`notes:changed` 全量广播 + 每次重建托盘菜单（`:163-169`、`:1049-1052`）；`pythonBin()` `spawnSync` 每候选 4s 同步阻塞启动（`:1454-1468`）。

### 6.2 P0 焦点：`main.js:2309-2319` 一处代码，四个后果

> **最该先向用户说明的三条（QA 交接第 6 条）**：L-1「悄悄改坏几何」、N-01「悄悄丢末段文字」、**N-04「主动给出错误的安全感」** —— 「已保存」只代表内容已提交到内存，不代表已写入磁盘；磁盘异常时界面仍显示已保存，用户因此不会备份、不会重试、会放心退出，把前两条的危害放大。

| 后果 | 机制 | 证据 |

| ① 几何污染（L-1） | 收纳态窗口为 50 DIP 窄条，`before-quit` 无条件写回 `note.bounds`；`commitBounds`（`:877-879`）本有双 guard 却被绕开 | `main.js:594-600`、`:2316` |
